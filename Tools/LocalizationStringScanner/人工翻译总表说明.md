# 人工翻译总表

在现有工具面板中打开「资源 / 语言国际化扫描工具」。

## 首次使用

1. 主语言默认 English。首次打开读取已有 English.xlsx 中的 Key 和英文；已有总表后以总表为准。
2. 点击「扫描文本」。扫描现有 Prefab 的 UIStringKey、标记 i18n 的数据表以及指定国际化调用。它不是所有场景、所有 C# 字符串的通用提取器。
3. 补齐新增条目的英文。只有确定新 Key 就是英文原句时，才勾选「新增 Key 本身就是原文」。独立 Key 不会被擅自当作英文。
4. 添加目标语言，点击「导出 / 更新总表」。
5. 将 `AAAGameData/Translations/Localization.xlsx` 交给翻译人员，填写 Translations 工作表。第一列 Key 默认隐藏，英文列和表头固定。
6. 翻译完成后，在工具中「导入并生成…」选择返回的文件；也可以把完成的文件放回上述固定路径。Unity 打开且自动生成启用时，保存后约 2–3 秒自动处理。Unity 关闭期间的变化会在下次打开后检查。

## 输出与配置

- 分语言 Excel：`AAAGameData/Languages/<Language>.xlsx`，兼容原有的锁定 / Key / Value 格式。
- 运行时文件：`Assets/ArrowGame/Language/<Language>.json`；AppConfigs.LoadFromBytes 启用时同时生成 `.bytes`。
- 新语言自动加入 AppConfigs 的语言加载列表。游戏语言选择表 ArrowLanguagesTable、字体覆盖与界面布局仍需按实际语言配置和验收。
- 总表是人工维护入口。不要同时手改生成后的单语言表。已有总表时窗口中的旧版 GPT 操作禁用，避免两个来源互相覆盖。
- 自动导入不会重写正在 Excel 中打开的总表。分语言生成文件若被占用，请关闭这些文件，然后手动导入重试。

## 填写约定

- 可以整行排序、调整完整语言列的位置。禁止单独排序译文列，否则同一行的含义会错位。
- 不要修改隐藏 Key、_Source 或 _Metadata；禁止删除行和修改语言表头。正常操作下，这些结构变化会被校验拦截。
- 巴西葡语为 PortugueseBrazil，葡萄牙葡语为 PortuguesePortugal，不使用两个相同的 Portuguese 表头。
- 每次重新导出生成新版本；旧版本的外部翻译文件不会覆盖新总表，请把译文合并进最新模板。
- 空译文保留已有译文；没有旧译文时阻止生成。不会自动用英文假装完成翻译。
- 原文变化会要求复核所有译文。确认后把该行「状态」设为「已复核」。已复核的原文再次变化时，可能要求重新导出刷新原文基线，再复核。
- `{0}` 等占位符可调整位置但不能遗漏；富文本标签必须完整、正确嵌套。换行数量及前后空白需保留。不接受公式。
- 重新扫描并导出时，未扫描到的非锁定行及其译文会自动清理（包括待复核行）；锁定填 1 保留手动条目。不重新扫描时不会自动清理。
- 从窗口移除语言选择不会删除总表已有语言列，防止误删译文。已废弃行按扫描结果自动清理，已有语言列继续保留。

## 故障处理

工具底部显示结果，Console 显示详细行号、Key、语言和原因。整个总表校验通过后才生成文件。输出文件会预先检查可写性，再批量替换；写入失败尝试回滚，回滚受阻时会保留备份并报告位置。

窗口原文尚未导出时，若外部总表已更新，工具会拒绝覆盖；请先保存自己的修改记录，再重新载入总表。

## 开发验证

Windows 下执行 `Tools/LocalizationStringScanner/Tests/Run-TranslationTests.ps1`。使用项目 Unity 自带编译器与 Mono，不安装额外依赖；项目需先在 Unity 中完成过导入。脚本验证真实 Excel 往返、语言列/行调序、结构错误、原文复核、空译文、占位符、锁文件保护和项目现有语言表兼容性，再编译编辑器程序集。测试输出只写入 `Temp/LocalizationVerification`，不改游戏语言文件。
